## nv29 Solstice validation

- Activation: epoch 4109133, 2026-09-28 12:59:30 UTC ([announcement](https://github.com/filecoin-project/community/discussions/74#discussioncomment-18565956)).
- 2026-09-24: Calix shipped nv29 readiness (data-driven upgrade schedule, countdown) and a chain finality panel.
- 2026-09-28 13:36 UTC: Calix post-upgrade audit live. All 16 nv29 actor code CIDs were cross-checked against an independent `lotus state actor-cids` output and matched. The audit tooling refuses to publish if any CID diverges.
- Post-upgrade: Calibration producing blocks normally on nv29, no fork, SP test target producing blocks across the boundary. The faucet needed no changes.

## Incidents

- **2026-09-02, 22:34 to 23:29 UTC, SP test-target status not OK.** Calix reported t0143103 as not active for about 55 minutes (12 probes). No sectors were faulted and the miner recovered on its own. Root cause was not identified. This used about 13% of the budget, below the post-mortem threshold.
- Isolated single-probe failures otherwise, none longer than 5 minutes.

## Faucet usage

- Drips sent: 4 tFIL drips totalling 16,000 tFIL, and 10 USDFC drips totalling 16,200 USDFC.
- No 429 rate-limit rejections on authenticated drips. Unauthenticated `GET` requests to drip URLs (crawlers and people opening API links in a browser) are rejected with 404 as intended and are not counted as failures.
- Dispenser reserves stayed above the configured minimums all month.

## Drip latency note

Same measurement as August: end-to-end response time, which includes waiting for the receipt after inclusion. All 3 tFIL drips completed in 59 to 65 s end to end, and every authenticated drip requested in September succeeded. Rate limits are set deliberately (one drip per asset per address and IP per 24 hours, with higher quotas for integration keys) and are not being changed.
